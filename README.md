# stock-briefing

국내주식 데이터를 수집하고 지표·보유량·설정 예산으로 제안을 계산해 매일 **08:30 KST 텔레그램 개인 대화**로 전달합니다. 카카오와 텔레그램의 요청은 같은 공통 명령 처리기를 사용합니다. 개인용 대시보드에서 저장된 시장 분석과 관심종목을 확인할 수 있으며, 비밀 키 입력에는 별도의 일회용 HTTPS 화면을 사용합니다.

## 구현 범위

- 한국투자증권 조회용 REST 어댑터: 토큰 발급·암호화 캐시, 거래소 일정, 수정주가 일봉 페이지 조회, 최근 확정 기관·외국인 수급, 선택 계좌의 잔고 연속조회
- DB 증분 수집: 처음에는 52주 계산에 필요한 과거 구간을 채우고, 이후에는 빠진 거래일만 요청; 일봉·수급 별도 upsert
- 이동평균·교차, 52주 범위·전일 위치 변화, 거래량 비율, 기관·외국인 순매수·직전 구간 비교
- 설명 가능한 7개 조건 점수와 정수 수량 계산: 보유금액 한도, 공통 매수 예산, 비용, 매도 비율 반영
- 데이터·보유량·전략 설정 누락 시 `데이터 확인 필요`; 이전 의견을 최신 제안으로 재사용하지 않음
- API 스케줄러의 수집 → 분석 → DB 저장 → 텔레그램 발송; 발송일별 예약으로 중복 방지
- 관심종목·보유량·추적 계좌·전략·알림 관리, 오늘 브리핑 자동 생성·이력·상태 조회
- 채널·사용자·대화에 묶인 5분 일회용 변경 확인, 텔레그램 update 중복 응답 캐시
- 종가 기반 모의 성과: 당시 제안 가격·수량·정책·비용 스냅샷, 설정 거래일 후 관측 가격 평가
- 주문 중지·한도 설정 및 **제출 불가 미리보기**. 실제 주문 API는 구현에 포함하지 않음
- PostgreSQL 트랜잭션·수집 잠금, 제한된 API 재시도, 비밀 URL 로그 억제, pg_dump 백업

**실계좌 API 키/권한 검증과 투자 전략·예산 설정은 운영자 설정이 필요합니다.** 임의의 투자 기간·가중치·예산을 자동 기본값으로 적용하지 않습니다. 미래에셋 국내주식 API는 확인된 명세·개인 이용 권한이 없어 지원 불가 상태를 안내하는 어댑터만 제공합니다. 모의 KIS 환경은 일정·수급 지원이 확인되지 않으면 분석을 보류합니다.

## 운영 구성: API · PostgreSQL · 텔레그램

- **api**: 웹/API, 갱신 큐, 매일 08:30 Asia/Seoul 정기 분석·발송을 담당합니다.
- **db**: PostgreSQL 전용 컨테이너와 영속 볼륨입니다. 호스트 포트는 공개하지 않습니다.
- **telegram**: 텔레그램 명령·버튼을 수신합니다. 분석·설정·발송 기록은 같은 PostgreSQL을 사용합니다.

worker 프로필과 새 systemd 타이머 설치는 제거했습니다. 기존 운영 서버는 일반 업데이트 버튼을 먼저 누르지 말고
[SQLite → PostgreSQL 일회성 이전 절차](POSTGRES_MIGRATION.md)를 완료해야 합니다.
이전 완료 표시가 없는 DB에서는 API/텔레그램 시작을 중단해 빈 DB로 운영되는 일을 방지합니다.
기존 SQLite 원본·백업과 증권사 암호화 master.key는 보존합니다.

이전 후 업데이트는 대시보드의 Compose 업데이트를 사용합니다. CLI를 사용할 때도 컨테이너 라벨의
전체 파일 순서(기존 override·관리 환경변수·compose.scheduler.yaml)를 유지합니다.
api·telegram 이미지를 빌드한 뒤 db·api·telegram을 올리며, 정기 분석은 API 이미지에 포함됩니다.

API는 08:30 이후 시작되면 당일 미발송분을 보완합니다. 자정 이전 당일만 보완하며 과거 날짜를 소급 발송하지 않습니다.
PostgreSQL 세션 잠금과 기존 발송 예약을 함께 사용합니다. sent/pending/review_required가 있는 날은 자동 재발송하지 않습니다.
알림 OFF 또는 아직 봇을 시작하지 않은 경우는 발송하지 않습니다. 기능을 켜거나 봇을 시작하면 다음 분 단위 확인에서 보완할 수 있습니다.

## 첫 분석 설정

`도움말`, `메인`, `메뉴`는 메인 카테고리 선택 목록을 보여줍니다. 텔레그램은 텍스트 목록을 중복 출력하지 않고 짧은 제목과 개별 버튼으로 표시합니다. 메인 메뉴는 2열, 하위 항목은 1열로 배치하고 메인·취소 버튼은 마지막 줄에 둡니다. 버튼별 영역은 텔레그램 기본 모양을 사용하며 글꼴 크기·아이콘 크기·테두리 두께는 봇에서 지정하지 않습니다. 카테고리 이름이나 번호를 보내면 하위 항목을 보여주고, 하위 항목 이름이나 번호를 보내면 실행합니다. 예를 들어 `브리핑`은 `오늘 브리핑`, `브리핑 이력`, `제안 보기` 메뉴를 보여주며, `오늘 브리핑`은 최신 데이터를 확인해 당일 전체 브리핑을 새로 생성하고 결과를 바로 보여줍니다. 추가 인자가 필요한 항목은 입력 형식을 안내하고, 설정·계좌·보유량 변경의 기존 확인 절차는 그대로 사용합니다.

`오늘 브리핑, 서비스 상태`처럼 여러 명령을 입력하면 `명령어가 2개 입니다. 선택해주세요.`와 번호 목록을 보여줍니다. 선택 전에는 어느 명령도 실행하지 않으며, 번호 또는 전체 항목명으로 하나만 실행합니다. 쉼표·줄바꿈·세미콜론·`그리고`·` / ` 구분을 지원하며, 명확히 구분되는 조회·고정 인자 명령은 같은 줄에서도 인식합니다. JSON 내부의 쉼표와 종목명 안의 명령 단어는 추가 명령으로 해석하지 않습니다. 자유 형식 종목명이 있는 명령은 구분자를 사용하세요.

선택은 사용자·채널·대화별로 저장되고 5분 뒤 만료됩니다. `취소`는 현재 선택을 종료하고 `메인`은 첫 메뉴로 돌아갑니다. 텔레그램은 긴 조회 결과를 여러 메시지로 모두 전송합니다. 카카오는 긴 결과를 1,000자 이내로 나누며 `다음`을 보내 나머지 내용을 조회할 수 있습니다. 새로운 명령을 보내면 이전의 선택·이어보기 상태를 종료합니다.

1. 봇에 `증권사 연결 한국투자증권`을 보내고 일회용 HTTPS 화면에 키·시크릿·계좌번호를 입력합니다. 키는 암호화 저장됩니다. 이 단계는 토큰 발급만 검증하며, 계좌의 조회 권한은 추적 선택 후 첫 조회에서 검사합니다. 계좌 자동 열거 API를 가정하지 않으므로 각 계좌를 화면에서 등록합니다. 새 연결 등록은 기존 계좌 추적을 중지하므로 필요한 계좌를 다시 선택합니다.
2. `추적 계좌 보기`로 마스킹된 계좌와 ID를 확인하고 `추적 계좌 추가 KIS-...` → `확인 코드`를 보냅니다. 미선택 계좌는 조회하지 않습니다. 계좌 연동을 쓰지 않는다면 `보유량 설정 005930 0`처럼 **0주도 명시적으로 확인**합니다.
3. `관심종목 추가 005930 삼성전자`로 관심종목을 등록합니다. 추적 계좌 보유종목도 분석 대상에 포함됩니다. 종목명은 표시용이며 코드 유효성은 데이터 조회에서 확인합니다.
4. `설정 도움말`을 보고 전체 전략 JSON을 `설정 변경 {JSON}`으로 보내고 확인합니다. 운영자 로컬 설정은 `python -m app.cli import-strategy --file strategy.json`도 지원합니다. JSON 파일을 컨테이너 `/data/strategy.json`에 놓으면 `docker compose exec -T api python -m app.cli import-strategy --file /data/strategy.json`으로 등록할 수 있습니다. 변수와 규칙은 [docs/implementation.md](docs/implementation.md)에 정리했습니다.
5. 텔레그램에서 `오늘 브리핑`을 입력하면 데이터를 갱신하고 새 결과를 바로 받습니다. 과거 저장 결과는 `브리핑 이력`으로 확인합니다. 데이터 수집량에 따라 응답까지 시간이 걸리며 카카오의 짧은 응답 제한에는 추가 콜백 연동이 필요합니다.

직접 실행해서 DB 생성만 확인하려면:

```bash
docker compose exec -T api python -m app.cli generate-briefing
# 당일 정기 발송 기록을 남기는 전체 실행:
docker compose exec -T api python -m app.cli run-daily
```

`send-test`, `inspect-telegram-id`, `save-briefing`, `send-briefing`은 기존 전달 경로 점검용으로 유지합니다. 수동으로 저장한 테스트 문구를 그대로 보내려면 `send-briefing`을 명시적으로 호출합니다. run-daily는 수동 문구 대신 새 브리핑을 생성합니다.

## 텔레그램 로그 조회

- `로그 보기` 또는 `지금 로그 보기`: 현재 시각부터 최근 3분
- `로그 보기 10분`: 현재 시각부터 최근 10분 (1~10080분)
- `로그 보기 09:05`: 오늘 한국 시간 09:05:00부터 09:05:59까지의 로그
- `상태` 메뉴의 `로그 보기` 항목으로도 최근 3분을 바로 조회합니다.

업데이트 후 실행한 API·텔레그램·API 정기 스케줄러의 브리핑, 전략 검증, 텔레그램 polling 진단을 공통 DB에 기록합니다. 기존 Docker 표준 출력 로그를 소급해서 읽지는 않습니다. HTTP 요청 URL이나 인증정보가 포함될 수 있는 외부 라이브러리 로그는 저장하지 않으며, 기존 허용 사용자·개인 대화 제한을 그대로 적용합니다. 로그는 7일 보관하고, 조회량이 많으면 최신 최대 200건·약 24,000자만 표시합니다. 더 좁은 시간으로 다시 조회할 수 있습니다. 텔레그램에서는 긴 응답을 여러 메시지로 나눠 전송합니다.

기능별 진단 로그는 명령 처리·권한 거부·중복 처리, 설정 확인/적용,
증권사 연결/인증, 일봉/수급/잔고 수집, 지표·점수 판단, 수량 산정,
모의 성과 평가, 갱신 작업, 백업, 텔레그램 발송을 기록합니다.
`Feature event`의 `trace`는 같은 작업에 속한 로그를 연결하며,
`feature`/`status`는 실행 단계, `elapsed_ms`는 소요시간입니다.
실패는 예외 종류와 traceback의 파일명·줄 번호·함수명을 기록하고, HTTP 응답은 상태코드·시도 횟수를 기록합니다.
분석 로그에는 종목코드·기준일·지표·신호·가중치·매수/매도 기준 점수를 남깁니다.
발송 생략, 입력 거부, 처리 중/캐시 응답은 별도 상태로 구분합니다.
명령 원문, 확인 코드, 등록 링크, 인증키·토큰, 계좌번호, API 원문 응답은
기능 로그에 기록하지 않습니다. 정상 상태의 빈 텔레그램 polling은 기록하지 않습니다.

Python의 ERROR 이상 로그, 기능 실행 중 예외, 처리되지 않은 CLI·스레드·asyncio 예외와
Uvicorn 오류도 같은 `로그 보기` 명령으로 조회합니다. traceback은 예외 체인과
파일명·줄 번호·함수명을 포함합니다. 인증정보 노출 방지를 위해 예외 메시지,
소스 코드와 지역변수는 저장하지 않으며, 허용 목록 밖의 일반 오류 메시지도 생략합니다.
`print()` 출력과 일반 외부 라이브러리 INFO/WARNING 로그는 수집하지 않습니다.
업데이트 전 Docker 로그와 DB 초기화 이전의 시작 오류는 소급 수집하지 않습니다.

## 운영·백업

API의 시작 로그에서 Daily scheduler started와 day/result 기록을 확인합니다.
정기 발송 기록은 PostgreSQL delivery_runs에 저장됩니다. pending 또는 review_required는 실제 텔레그램 대화 확인 후 운영자가 판단해야 하며 자동 삭제·재전송하지 않습니다.

PostgreSQL 백업·복원과 장애 시 전환 절차는 [이전 문서](POSTGRES_MIGRATION.md)를 따릅니다.
DB 백업과 별도로 master.key를 보호해야 저장된 증권사 인증정보를 복호화할 수 있습니다.
SQLite 백업 명령은 기존 SQLite 모드에서만 사용할 수 있습니다.

### 관심종목 공개 시세 브리핑

증권사 API·계좌 연결 없이 관심종목 등록 후 `오늘 브리핑`으로 조회합니다. 종목명 → 종가 기준일 → 종합 의견 → 가격·추세·거래량·가격 위치·최근 흐름·주의점 순서로 표시합니다. 실시간 가격이 아닌 전 거래일 공개 일봉을 사용합니다.

- 가격과 전일 등락률, 5·20·60·120일 이동평균 위치 및 단기/장기 교차
- 직전 20거래일 평균 대비 거래량, 52주 최고·최저가와 종가의 거리
- 5·20·60거래일 기준 1주·1개월·3개월 수익률
- 직전 20거래일 고점 돌파·저점 이탈, 최근 20일 일간 수익률 표준편차와 직전 20일 대비 확대 여부
- 매수 검토·관망·매도 검토와 판단 지표, 확인 불가 항목 표시

전략 설정이 비어 있으면 관심종목 전용 기본 기준(5/20일선, 거래량 20일·1.5배, 52주 위치 하위 20%/상위 20%, 각 신호 1점, ±2점)을 사용합니다. 전략이 등록되어 있으면 기존 가격·거래량 기준을 사용합니다. 기관·외국인 수급, 계좌 잔고·평균 매입가·손익·주문금액·체결 내역은 제외합니다. 52주 등 이력이 부족한 지표는 판단에서 제외하며, 이동평균 교차나 유효 거래량이 부족하면 의견을 보류합니다. 보유종목은 기존 전체 전략 설정이 필요합니다.

### 종목명으로 관심종목 추가

`관심종목 이노스페이스 추가` 또는 `관심종목 추가 이노스페이스`로 종목코드를 자동 조회합니다. 한국투자 API가 연결돼 있으면 종목정보를 우선 확인하고, 연결이 없거나 API 조회가 실패하면 공식 공개 코스피·코스닥 종목 목록을 사용합니다. API는 코드 입력이 필요하므로 처음 보는 이름은 공개 목록에서 코드 후보를 찾은 뒤 API로 확인합니다. 공개 목록은 24시간 캐시하며 별도 API 키가 필요 없습니다.

공백과 영문 대소문자를 무시한 이름 전체 일치를 사용합니다. 유사 이름을 임의로 선택하지 않으며, 중복 이름·검색 실패·목록 조회 실패 시 6자리 코드를 요청합니다. API와 공개 목록의 종목명이 다르면 코드 확인을 요청합니다. 국내 숫자 6자리 종목코드만 지원합니다.

목록 출처: [한국투자증권 공식 종목코드 자료](https://github.com/koreainvestment/open-trading-api/tree/main/stocks_info). API 확인: 주식기본조회 `search-stock-info` (`CTPF1002R`).


### 코스피 추세 반영

관심종목·보유종목 모두 같은 기준 거래일의 공개 코스피 일봉을 사용합니다.
20·60일 이동평균의 배열과 20일선 기울기, 스토캐스틱(14,3,3)의 K/D와 K의 방향으로
상승·하락·반등·하락 전환·횡보를 표시합니다. 사인 곡선을 맞추어 미래 가격이나 주기를 예측하지 않습니다.
이동평균 신호와 파동 신호의 합을 -1~+1로 제한해 기존 종목 점수에 더한 후 기존 매수·매도 기준을 적용합니다.
상충하는 신호는 상쇄되며, 단순 과매도만으로 매수 점수를 주지 않습니다.
코스피 기준일 불일치·일봉 부족·거래일 누락 시 의견과 수량을 보류합니다.
브리핑과 저장된 판단 지표에는 코스피 지수·단계·이동평균·K/D·반영 점수를 함께 남깁니다.

### 관심종목 한눈에 보기

`오늘 브리핑`의 관심종목 상세 앞에 종합 의견별 종목 수와 전일 대비 최대 상승·하락 종목을 표시합니다. 비교 대상은 등록된 관심종목이며, 상승·하락 종목이 없는 방향은 생략합니다. 수익률이 같으면 종목코드 순으로 한 종목을 표시합니다.

이동평균 상향·하향 교차와 직전 20거래일 고점 돌파·저점 이탈을 모아서 보여줍니다. 고점·저점과 같은 가격은 돌파·이탈로 집계하지 않습니다. 데이터 조회 실패 종목은 의견 보류에 포함하고, 확인할 수 없는 지표는 신호 및 등락 비교에서 제외합니다. 일부 지표만 있는 의견 보류 종목도 확인된 가격·교차 신호는 표시할 수 있습니다. 요약은 이번 생성 결과만 사용하며 기존 매매 점수·예산·수량 계산은 바꾸지 않습니다.

### 빠른 메뉴와 종목 선택

`빠른 메뉴`, `바로가기`, `/quick`으로 오늘 브리핑·관심종목 보기·보유종목·종목별 제안 선택·서비스 상태·연동 상태·버전을 번호로 선택합니다. 메뉴를 여는 것만으로는 갱신이나 조회를 실행하지 않습니다. 기존 메인 카테고리 번호는 유지됩니다.

`종목별 제안 선택`은 브리핑 메뉴에서도 이용할 수 있습니다. 관심종목, 수동 보유종목 및 저장된 제안에 등장한 종목을 코드 순으로 표시하고, 번호로 선택하면 해당 코드의 저장된 보유종목 제안과 관심종목 의견을 각각 보여줍니다. 과거 저장 제안도 포함하므로 상세의 기준일·생성 시각을 확인하세요. 아직 분석하지 않은 종목은 `오늘 브리핑` 실행을 안내합니다. 메뉴는 5분 후 만료되고 `취소`로 종료합니다. 조회 시 증권사 연결이나 새 데이터 수집을 시작하지 않습니다.

### 텔레그램 버튼 메뉴와 의견별 브리핑

`메뉴`를 입력하면 메시지 안에 메인 카테고리 버튼이 표시됩니다. 하단 고정 키보드는 사용하지 않습니다. 카테고리·세부 항목·겹치는 명령·종목별 제안 선택은 버튼으로 선택하고, 종목명·수량·설정 JSON은 안내에 따라 입력합니다. 기존 명령어와 번호 선택도 계속 지원합니다. 설정 변경은 기존 확인 절차를 거치며 확인 버튼으로 적용할 수 있습니다. 일반 선택 메뉴는 5분 후 만료되고 다른 메뉴를 열면 이전 선택 버튼은 만료됩니다.

텔레그램의 `오늘 브리핑`과 정기 발송은 `매수 N개`, `매도 N개`, `관망 N개` 버튼을 먼저 보여줍니다. 버튼을 누르면 해당 의견에 속한 종목의 판단 내용을 모두 보내며, 긴 내용은 여러 메시지로 나누어 전송합니다. 데이터 부족 종목은 관망에 섞지 않고 `의견 보류 N개`로 표시합니다. `전체 보기`는 원본 브리핑 전체를 제공합니다. 각 의견의 개수는 중복 종목코드를 한 번만 세며 보유·관심 분석 내용은 각각 표시합니다. 동일 종목의 두 분석 의견이 다르면 각각 해당 의견에 포함됩니다.

버튼은 생성 당시 저장한 결과를 조회합니다. 같은 날 새로 갱신하거나 다음 날이 되어도 과거 브리핑 버튼은 당시 결과를 보여주며 새 데이터를 수집하지 않습니다. 업데이트 전 생성되어 분류 정보가 없는 정기 브리핑은 기존 전체 텍스트로 발송합니다. 버튼도 기존 텔레그램 허용 사용자·개인 대화 제한을 적용합니다.

### 관심종목 3년 고점과 당시 코스피 비교

공개 종목·코스피 일봉을 각각 최대 1,200거래일 요청해 최근 3년과 과거 지표 계산에 필요한 선행 이력을 확보합니다. **52주 신고가 3개는 기준일로부터 서로 겹치지 않는 52주씩 3구간의 최고가**로 정의합니다. 각 구간은 364일이며 최고가는 장중 고가 기준, 같은 최고가가 여러 번이면 가장 최근 날짜를 사용합니다. 최근 세 번의 신고가 갱신 거래일을 뜻하지 않습니다.

각 최고가의 금액·날짜·현재가의 고점 대비 등락률, 해당 날짜까지의 코스피 20·60일선·스토캐스틱 기반 추세를 계산합니다. 고점 당시와 현재의 종목·코스피 20거래일 수익률 및 초과수익률(%p), 코스피 추세 점수 차이를 함께 표시합니다. 과거 고점의 지표에는 고점 날짜 이후 관측치를 사용하지 않습니다.

기존 종목 점수와 현재 코스피 점수에 추가 비교 점수를 최대 ±1점 반영한 후 기존 매수·매도 임계값을 적용합니다. 추가 기준은 다음과 같습니다.

- +1점: 현재가가 3구간 최고가 중 최댓값의 95% 이상이고, 현재 20거래일 코스피 대비 초과수익률이 0과 세 고점 당시 초과수익률 중앙값보다 높으며, 현재 코스피 신호가 0 이상이면서 당시 신호 중앙값 이상일 때.
- -1점: 현재가가 같은 최고가의 85% 이하이고, 현재 초과수익률이 0과 당시 중앙값보다 낮으며, 현재 코스피 신호가 0과 당시 신호 중앙값보다 모두 낮을 때.
- 그 외 0점. 신규 상장·거래일 누락·과거 코스피 부족 등으로 3구간 비교가 완전하지 않으면 추가 점수만 제외합니다. 기존 필수 지표 부족으로 보류된 의견은 유지합니다.

이 추가 점수는 관심종목에만 적용합니다. 보유종목 수량 계산과 실제 주문 기능은 변경하지 않습니다.

## 개인용 웹 대시보드

기존 FastAPI 서버의 `/stock-briefing/`에서 휴대폰과 PC용 대시보드를 제공합니다. 별도 프런트엔드 빌드나 DB 이전 없이 텔레그램과 같은 PostgreSQL DB를 사용합니다.

- 대시보드: 저장된 전체 브리핑, 관심종목 수, 코스피 추세·기준일, 갱신 진행 상태
- 관심종목: 종목명 전체 또는 영문·숫자 6자리 코드로 추가, 종가·전일 등락률·판단 기준일 확인, 확인창 후 제거
- 브리핑 이력: 날짜별 전체 내용과 30개 단위 이전 기록 조회
- 갱신: 기존 작업 큐에 요청하고 10초 간격으로 완료 상태 확인. 텔레그램 발송이나 실제 주문은 실행하지 않습니다.

### 접속 설정

1. `.env`에 `DASHBOARD_ALLOW_HTTP_PRIVATE=1`, `DASHBOARD_USERNAME=admin`, `DASHBOARD_PASSWORD`를 설정합니다. 비밀번호는 12자 이상의 별도 무작위 문자열을 사용하세요. `python -c 'import secrets; print(secrets.token_urlsafe(32))'`로 생성할 수 있습니다. 실제 값은 저장소에 커밋하지 마세요.
2. 기존 서버 업데이트 절차에 따라 api 컨테이너를 다시 생성합니다. API는 호스트의 `127.0.0.1:8001`에서 수신하고 컨테이너 안에서는 `8000`을 사용합니다.
3. Caddy 설정 예시처럼 기존 도메인/가계부 경로는 API의 `127.0.0.1:8001`로 전달하고, WireGuard 전용 HTTP 접속을 위해 별도 `:8081` 리스너를 추가합니다. 서버 방화벽에서 TCP `8081`은 WireGuard 인터페이스/피어에서만 허용하세요. Caddy 예시는 [deploy/Caddyfile.example](deploy/Caddyfile.example)을 참고하세요.
4. WireGuard에 연결한 기기에서 `http://<WireGuard 서버 IP>:8081/stock-briefing/`로 접속하고 로그인 페이지에 사용자명과 비밀번호를 입력합니다. HTTPS 도메인에서는 `/stock-briefing/`로 접속하면 같은 로그인 페이지가 열립니다. 로컬에서는 `http://127.0.0.1:8001/stock-briefing/`로 확인할 수 있습니다.

비밀번호가 없거나 12자 미만이면 웹 화면과 API는 404로 비활성화됩니다. `DASHBOARD_ALLOW_HTTP_PRIVATE=1`은 사설 IP에서 HTTP를 허용합니다. 별도 Caddy 포트 `8081`은 기본 웹 포트 `80/443`을 사용하는 가계부 사이트와 겹치지 않도록 분리했습니다. 대시보드는 단일 운영자용으로 사용자별 데이터 분리를 제공하지 않습니다. 로그인은 HttpOnly·SameSite=Strict 쿠키로 12시간 유지되며 HTTPS에서는 Secure 속성을 적용합니다. 로그아웃 버튼은 현재 브라우저의 쿠키를 삭제합니다. 아이디 또는 비밀번호를 바꾸고 컨테이너를 다시 생성하면 기존 로그인 쿠키도 무효화됩니다. 로그인 실패는 접속 IP당 5분 동안 10회로 제한합니다(프로세스별 제한이며, 프록시 설정에 따라 여러 기기가 같은 IP로 집계될 수 있습니다). 비밀번호를 잊었다면 서버의 `.env`에서 `DASHBOARD_PASSWORD`를 확인하거나 새 값으로 변경한 뒤 api 컨테이너를 다시 생성하세요.
모든 화면·API 응답은 캐시를 금지하고, 외부 스크립트·폰트 없이 정적 파일을 함께 제공합니다. 데이터는 텍스트로 렌더링하고 변경 요청은 같은 출처의 전용 헤더를 요구합니다. 증권사 비밀 키·계좌번호·원본 서버 로그는 웹 API 응답에 포함하지 않습니다. 관심종목 변경은 기존 수집 잠금과 감사 로그를 사용합니다. 종목코드만 입력하면 이름은 코드로 표시되며 유효성은 브리핑 갱신 시 확인됩니다. 종목명 조회 실패·중복 시 코드를 요청합니다. 저장된 의견은 갱신 전까지 과거 데이터이며 종목별 기준일을 확인해야 합니다.
