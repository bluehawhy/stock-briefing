# 주식 브리핑 서버 업데이트 설명서

대상: bluehawhy/stock-briefing  
서버 경로: ~/source/stock-briefing  
작성일: 2026-10-12

## 1. 서버 업데이트

우분투 서버에 접속한 뒤 아래 명령어를 한 번에 복사해서 실행합니다.
텔레그램이 아니라 서버 터미널에 입력합니다.

```bash
cd ~/source/stock-briefing
git pull --ff-only origin main
bash scripts/update-server.sh
```

업데이트 스크립트는 최신 main을 가져온 뒤, 현재 커밋 ID와 빌드 시작 시각을 이미지에 기록합니다.
api·telegram·정기 실행 worker를 같은 정보로 빌드하고 api·telegram을 재시작한 다음 상태와 API 응답을 확인합니다.
main 브랜치가 아니거나 커밋되지 않은 변경이 있으면 중단합니다.

업데이트가 끝나면 텔레그램에 아래 명령어를 입력합니다.

```text
버전
```

응답 형식:

```text
빌드시간: yyyy-mm-dd hh:mm:ss
빌드번호: 40자리 커밋아이디
```

빌드시간은 한국시간(Asia/Seoul) 기준입니다. 빌드번호는 실행 중인 이미지에 포함된 코드의 커밋 ID이며, 컨테이너 재시작이나 이후 git pull만으로 바뀌지 않습니다.
빌드정보 없이 만든 이전 이미지나 로컬 실행은 정보 없음으로 표시됩니다.
이후 업데이트에도 위 스크립트를 사용하면 두 값이 자동으로 갱신됩니다.

api와 telegram이 모두 실행 중(Up)인지 확인합니다.
git pull 또는 빌드에서 오류가 발생하면 업데이트 완료로 보지 말고 오류 내용을 확인합니다.

## 2. 오늘 브리핑 생성 및 확인

텔레그램 챗봇에 아래 명령어만 입력합니다.

```text
오늘 브리핑
```

최신 데이터를 조회해 브리핑을 새로 생성한 뒤 결과를 바로 보내줍니다.
기존에 저장된 오류 브리핑을 그대로 다시 보여주지 않습니다.
데이터 수집량에 따라 응답까지 시간이 걸릴 수 있습니다.
생성한 결과는 저장되며 과거 기록은 브리핑 이력으로 확인할 수 있습니다.

새 브리핑은 보유종목과 관심종목을 구분해서 표시합니다.
보유종목은 수동 등록 보유량 또는 추적 계좌 기준으로 표시합니다.

관심종목은 증권사 API 키나 계좌 연결 없이 공개 일봉으로 분석합니다.
매수·매도·관망 의견과 판단에 사용한 이동평균, 가격 위치, 교차, 52주 범위, 거래량 추세만 표시하며 보유량·제안 수량·예산은 표시하지 않습니다.
기관·외국인 수급은 공개 일봉에 없으므로 관심종목 점수에서 제외합니다.
기존 전략의 가격·거래량 가중치와 매수·매도 점수 기준을 그대로 사용합니다. 전체 전략 설정이 없으면 의견을 보류하고 설정 안내를 표시합니다.
관심종목은 보유종목용 공통 매수 예산을 사용하지 않습니다.
보유종목 조회 실패 또는 증권사 API 키 누락이 관심종목 분석을 중단시키지 않습니다.

공개 일봉은 네이버 일봉 차트에서 가져오며 당일 진행 중인 일봉은 제외합니다.
삼성전자 공개 일봉의 실제 거래일을 기준으로 기준일 및 52주 데이터 누락을 확인합니다.
공개 데이터 조회 실패, 기준일 불일치, 거래정지 또는 52주 이력 부족 시 해당 종목의 의견을 보류합니다.

## 3. 문제가 발생했을 때

서버 터미널에서 아래 명령어를 실행합니다.

```bash
cd ~/source/stock-briefing
docker compose ps
docker compose logs --tail=80 api telegram
```

- 챗봇이 응답하지 않으면 telegram 서비스 상태와 로그를 확인합니다.
- 브리핑 생성이 실패하면 api와 telegram 로그를 확인합니다.
- 오늘 브리핑 생성이 실패하면 응답에 나온 사유와 서버 로그를 확인합니다.
- 종목에 데이터 확인 필요가 표시되면 함께 나온 사유를 확인합니다. 코드 업데이트만으로 보유량 등록이나 증권사 연결이 자동으로 완료되지는 않습니다.

문제 확인을 요청할 때는 오류 메시지와 위 로그를 함께 전달합니다.
인증키, 토큰, 계좌번호 등 민감한 정보는 가리고 전달합니다.

## 4. 업데이트할 때의 순서

1. 서버 터미널에서 업데이트 명령어 실행
2. api와 telegram 실행 상태 및 API 응답 확인
3. 텔레그램에서 버전으로 빌드정보 확인
4. 오늘 브리핑 입력 후 새로 생성된 결과 확인
