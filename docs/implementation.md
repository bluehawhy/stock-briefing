# 구현과 운영 설정

2026-10-07 구현 상태. 요구사항 문서 `stock-briefing.md`와 `docs/design.md`의 브리핑·관리 흐름을 구현했으며, 아래 외부 의존 범위와 지원 제한을 구분한다.

## 전략 JSON

운영 기본 전략은 없다. 다음 모든 필드를 운영자가 결정하고 등록해야 한다. 숫자는 유한 값이어야 하며 원·주·기간은 정수로 검증한다. 기존 전체 전략을 등록한 뒤에는 `설정 변경 {일부 필드}`로 변경할 수 있다.

| 필드 | 의미·허용 범위 |
|---|---|
| short_ma / long_ma | 단순 이동평균 기간, 1 ≤ 단기 < 장기 ≤ 250 거래일 |
| volume_window | 당일을 제외한 평균 거래량 기간, 1~250 거래일 |
| flow_window | 기관·외국인 순매수 합계 기간, 1~30 거래일; 직전 구간 비교를 위해 1일 추가 필요 |
| volume_ratio | 거래량 동반 추세 조건의 임계 배율, 0 초과 |
| range_buy_max / range_sell_min | 52주 고저 범위에서 매수/매도 조건 위치, 0 ≤ 매수 < 매도 ≤ 1 |
| buy_score / sell_score | 매수 1~가중치 합, 매도 -가중치 합~-1; 사이 점수는 관망 |
| weights | ma_trend, price_position, cross, range_position, volume, institution, foreign의 가중치 객체. 각각 0~100 정수, 합계 0 초과. 기본값 없음 |
| buy_budget | 이번 브리핑의 전체 매수 예산, 원, 0 이상 |
| max_position | 종목별 최대 보유금액, 원, 0 이상 |
| sell_fraction | 제안할 보유량 비율, 0 초과~1 |
| holdings_max_age_hours | 수동 보유량 확인 시각의 최대 경과 시간, 0 초과~8760시간 |
| evaluation_days | 모의 평가 시점, 제안 기준일 이후 1~250 거래일 |
| fee_bps / tax_bps / slippage_bps | 비용 가정, 각각 0~9999bps; 1bps=0.01% |

설정 예시의 실제 숫자는 운영 정책으로 제공하지 않는다. `tests/conftest.py`의 고정 숫자는 테스트 전용이다. 현금 API를 가정하지 않고 명시된 `buy_budget`만 사용한다. 예산은 종목코드 순서로 배분하며, 기존 보유금액과 매수 측 수수료·슬리피지를 반영해 정수 주 단위로 내림한다. 매도 제안은 `보유량 × sell_fraction`을 내림한다. 설정값 0원은 유효하며 수량 0주의 이유를 표시한다.

## 고정 규칙 v1

각 조건 신호는 +1, 0, -1이며 사용자가 명시한 가중치를 곱한 뒤 합산한다. 단순 이동평균 기간·조건 임계값·가중치·최종 점수 구간을 모두 설정으로 받는다. 아래 조건 목록의 ±1은 가중치 적용 전 신호를 뜻한다.

1. 단기 이동평균이 장기 위/아래: +1/-1 (같으면 0)
2. 종가가 장기 이동평균 위/아래: +1/-1
3. 직전과 당일 단기·장기선의 상향/하향 교차: +1/-1
4. 52주 위치가 `range_buy_max` 이하 / `range_sell_min` 이상: +1/-1
5. 거래량 배율이 임계값 이상일 때 이동평균 추세 방향으로 +1/-1
6. 기관 순매수 합계 양수/음수: +1/-1
7. 외국인 순매수 합계 양수/음수: +1/-1

52주는 기준일 포함 최근 365일 구간의 고가·저가로 계산한다. 52주 안의 모든 개장일 일봉, 이동평균 교차용 직전 데이터, 수급 현재/직전 구간과 최신 보유량이 있어야 제안을 만든다. 신규 상장, 거래정지·0 거래량, 수급 미제공 종목·ETF는 필요한 데이터가 없으면 보류된다. 52주 위치 변화와 직전 수급 비교는 표시 지표이며 추가 점수는 부여하지 않는다.

## 데이터·공급자

한국투자 개인 REST의 아래 조회 요청만 구현한다. 주문 경로는 없다. 공식 개발자센터 문서의 endpoint/TR 형식을 기반으로 작성했고, 고정 응답 MockTransport로 계약을 검증했다. 운영자의 실계좌 응답 검증은 아직 수행하지 않았다.

| 기능 | 경로 | TR |
|---|---|---|
| 토큰 | `/oauth2/tokenP` | 해당 없음 |
| 거래소 일정 | `/uapi/domestic-stock/v1/quotations/chk-holiday` | CTCA0903R |
| 수정주가 일봉 | `/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice` | FHKST03010100 |
| 최근 확정 수급 | `/uapi/domestic-stock/v1/quotations/inquire-investor` | FHKST01010900 |
| 잔고 | `/uapi/domestic-stock/v1/trading/inquire-balance` | TTTC8434R / VTTC8434R |

[한국투자 API 문서](https://apiportal.koreainvestment.com/apiservice-category), [서비스 신청 안내](https://apiportal.koreainvestment.com/about-howto).

- 일봉은 최대 응답 건수에 맞춰 날짜를 뒤로 이동하며 페이지 조회한다. 잔고는 연속조회 헤더·커서가 끝날 때까지 조회해야 성공으로 처리한다.
- 수급은 최근 확정 구간만 공급자에 요청한다. 임의로 과거 52주 수급을 생성하지 않는다. 요구 기간을 제공하지 못하면 데이터 확인 필요로 보류한다. 거래일마다 누적 캐시한다.
- 거래소 일정을 DB에 저장하고 매일 필요한 새 날짜만 조회한다. 평일이라는 이유만으로 개장일로 추정하지 않는다. 달력 응답에 모든 날짜의 개장/휴장 여부가 없으면 보류한다.
- 일봉·수급은 종목·거래일별 upsert. 완전한 저장 데이터는 재요청하지 않는다. 상장 전 기간이나 공급자가 제공하지 않는 날짜는 누락으로 남아 재요청될 수 있다.
- 과거 수정주가·수급 정정의 자동 전수 재검증은 없다. 분할/병합 등 과거 가격 기준이 바뀌면 운영자가 캐시를 재검증해야 하며, 오래된 기준의 모의 성과를 실제 체결 손익으로 해석하지 않는다.
- 한 연결의 키로 접근 가능한 계좌는 사용자가 화면에서 등록한다. 계좌 자동 열거는 구현하지 않는다. 여러 등록 계좌 중 추적한 계좌만 조회·합산한다. 계좌 재등록은 추적을 재확인하도록 중지한다.
- 보유량 조회 실패 시 이전 잔고를 재사용하지 않는다. 추적 계좌가 없을 때만 수동 보유량을 사용하며, 0주도 확인 시각과 함께 저장한다.
- 토큰·키는 별도 600 권한 마스터 키로 Fernet 암호화하여 DB에 저장한다. 토큰 만료 5분 전에 새 토큰을 요청한다. 서버 간 동시 발급은 DB lease로 막는다.
- 요청은 약 0.55초 이상 간격으로 전송하고 네트워크 오류·429·5xx·호출 제한 코드에 최대 3회만 시도한다. 최종 오류는 응답 원문·키를 포함하지 않는다.

## 메시지·작업

권한은 기존 카카오/텔레그램 허용 ID 설정으로 같은 단일 운영자를 관리한다. **채널 간 자동 계정 연결은 구현하지 않는다.** 다른 사용자의 ID를 허용 목록에 넣으면 동일 운영자 데이터에 접근할 수 있으므로 여러 사용자 서비스로 사용하지 않는다. 카카오가 request ID를 제공하면 캐시하며, 제공하지 않는 요청에는 부작용이 없는 조회·idempotent 관심종목 변경·일회용 확인으로 보호한다. 텔레그램은 update ID와 처리 응답을 저장하여 동일 update의 설정 요청을 다시 생성하지 않는다.

브리핑 갱신은 SQLite 큐에 넣고 API의 background consumer가 처리한다. 중복 요청을 합치고 하나의 작업만 claim한다. 오래된 running 작업은 failed로 남긴다. 정기 worker와 요청 갱신은 수집 lease를 공유한다. 추적·전략·잔고·관심종목 변경은 갱신 중 적용하지 않아 분석 입력이 섞이지 않는다. 조회 명령은 API 재수집을 하지 않는다.

`오늘 브리핑`은 한국 날짜의 당일 기록만 조회한다. 과거 기록은 날짜를 명시한 `브리핑 이력`으로 조회한다. 전 거래일 기준은 예약 시각을 놓친 경우에도 유지하며 실행일 종가로 바꾸지 않는다. 정기 발송과 요청 브리핑은 분리된다.

## 모의 성과·주문 지원 제한

모의 기록은 해당 발송일·종목의 첫 유효 제안을 보존한다. 기준 종가로 진입하고 설정 거래일 뒤 관측 종가로 평가하는 가정이며, 양의 비용 반영 손익을 적중으로 정의한다. 수수료는 양방향, 세금은 매도 측, 슬리피지는 양방향에 적용한다. 매도 의견은 기존 주식을 매도하고 평가일 재매수한 가정의 회피손익이며 공매도 가상 체결이 아니다. 기준일 종가는 아침 제안 전에 관측된 가격이므로 실제 실행 가능 성과가 아니라 지표 평가용이다.

미평가/가격 누락은 적중률 분모에서 제외한다. 평가가 완료된 관측 가격과 당시 전략·비용은 이후 설정 변경에 따라 고치지 않는다. 제거된 관심종목의 과거 모의 기록은 보관하지만 더 이상 가격을 수집하지 않는 종목은 미평가로 남을 수 있다.

실제 주문을 켜는 옵션이나 주문 API는 제공하지 않는다. 주문 한도·당일 중지 및 같은 대화의 일회용 확인 흐름은 저장하지만, 실시간 가격 이탈·주문가능금액·미체결 예약 한도·상태 대조·정정·취소를 완료한 실주문 기능은 아직 없다. `주문 요청`은 제출 불가를 명시한 오프라인 미리보기이고, `주문 확인`은 비활성 상태를 안내할 뿐이다. 향후 실제 주문을 활성화하려면 이 검증과 실계좌 테스트를 추가 구현해야 한다.
